# Instructor Guide

## Workshop plan

| Segment | Full session | Short session | Facilitator action |
| --- | ---: | ---: | --- |
| Welcome, story, setup | 15 min | 10 min | Explain fiction, verify portal and notebook |
| Mission 1: Eyes Online | 35 min | 25 min | Demonstrate BGR, CLAHE and crop |
| Mission 2: Missing Clue | 45 min | 25 min | Compare scenes; detector weights are optional |
| Mission 3: Red Bag | 35 min | 25 min | Tune HSV thresholds; inspect false positives |
| Mission 4: Follow the Trail | 40 min | 25 min | Run clip and discuss candidate tracking |
| Final investigation and reveal | 20 min | 10 min | Collect five evidence categories; read reveal |
| Buffer and troubleshooting | 10-20 min | 10 min | Pair participants; switch to portal/demo as needed |

Full plan: about 3h25m plus optional buffer. Short plan: about 2h10m; omit deep parameter exploration, optional model inference, and some Level 2/3 challenge questions. Keep the four algorithm demonstrations and final evidence reasoning.

## Opening script

"Welcome, investigators. This case is a fictional training simulation. The portraits, frames, people and log are invented. OpenCV can help us process visible pixels and follow a colored region; it cannot tell us who committed a crime. Your task is to reconstruct this case using visual outputs and separately sourced case records."

"ARGUS has rebooted, but its camera frame is dark and its integrity report is compromised. At 23:42, something happened in Professor Rao's lab. First, recover what the pixels can tell us."

### Mission transitions

- To Level 1: "Before we identify anything, we need to see what the camera actually recorded. Enhance carefully: no filter can restore information that was never captured."
- To Level 2: "A readable timestamp is only one clue. Now compare the scene inventory, and be precise about which claims came from a detector versus a prepared case record."
- To Level 3: "The red backpack is now a candidate of interest. Find its color region, but keep the owner's name in the case file, not in the mask."
- To Level 4: "A still image cannot show direction. Follow the candidate across frames, and call a crossing only when you observe positions on both sides."
- To finale: "You have pixels, movement, a witness record and an ARGUS log. Which conclusions depend on more than one source?"

## Expected outputs and answers

- Level 1: source dimensions 720 x 420 x 3; clock reference reads 23:42 after CLAHE/cropping. The expected answer is scripted, not OCR-validated.
- Level 2: actual portal operation computes a pixel difference. With model setup, live YOLO inference runs on staged scenes or selected photos; the three bundled photos are useful for observing misses and false positives, not guaranteed detections. Ground truth says there are two people in the early synthetic scene, a phone, one early chai cup, two later cups, one red backpack and one secondary bag. These are scene annotations, not model detections. Prototype is represented in the inventory and is not an asserted COCO class.
- Level 3: two hue intervals catch red; at least one large candidate box surrounds the staged bag. Red labels and similar objects are possible false positives. Aarav is the owner according to case file.
- Level 4: steady clip is 70 frames at 10 FPS, 640 x 360; its red candidate crosses x=480 at frame 56 (5.6 seconds into the clip). Fast clip crosses near frame 52. Occlusion/distractor clip loses the candidate temporarily and crosses near frame 83. Exact outputs are calculated from video frames. Case record names Kabir; log asset says `23:44: CORRUPTION SCRIPT EXECUTED`.
- Final: culprit Kabir; owner Aarav; carrier Kabir; incident window 23:42; corruption log at 23:44. Select `ev-time`, `ev-scene`, `ev-owner`, `ev-trail`, and `ev-log`.

## Instructor checklist

- Run `python scripts/prepare_data.py`, `python scripts/verify_assets.py`, and `python -m pytest -q` before the session.
- For Level 2 model inference, run `python -m pip install -e ".[model]"` then `python scripts/setup_model.py` before participants arrive.
- Start `python scripts/server.py`; confirm `http://127.0.0.1:8000/app/` loads.
- Use Python 3.11 if installing on new laptops; the verified local run used Python 3.9.6.
- No YOLO model is required. Do not promise detector output without local weights.
- Set the facilitator override on the dashboard to skip ahead; in a mission use “MARK REVIEWED” to award the skip and unlock evidence.
- Leave the canonical solution guide closed until the final reveal.

## Common issues and demonstration fallback

If setup fails, pair participants and use the portal's **Run OpenCV Pipeline** controls (same Python modules, same local server). If their machine cannot run Python, project the facilitator machine's portal and notebooks. The video output is generated by actual tracking and can be rerun with `python scripts/run_demo.py`. Missing optional weights are normal; use prepared scene comparison, never fake model predictions. If a video codec cannot write MP4 on a participant machine, inspect the frame-based notebook output and use the generated facilitator reference.

## Final reveal script

"The red bag belongs to Aarav. Ownership did not identify its carrier. The staged sequence's red candidate crosses the exit line, while the separate fictional case record identifies Kabir as the person carrying it and connects him to the equipment. The prepared ARGUS log separately records corruption at 23:44. In this fictional case, these independent pieces point to Kabir. Our computer-vision code detected a red region and motion; it did not identify Kabir or prove a real crime."

## Early finishers

Ask participants to move the exit line, change minimum contour area, test the occluded frame, compare blur versus threshold, or explain why increasing detector confidence can remove true positives. Ask them to identify one false-positive mode and one limitation in the report.
